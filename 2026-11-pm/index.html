Room From Photos

Fast photo-matched parametric modeling

OFF-KILTER® research lab / November 2026

Goal: Build a 3D room model in near-real-time from just a few reference photos, but still with clean topology and light/materialization realistic enough for lighting studies.

Approach:

  • Solve room layout, placement, dimensions and lighting using a limited set of reference photos and the brand/model of a few items that have published dimensions.
  • Use the solved layout to generate a parametric 3D model with clean topology and place cameras that match reference photos. Decorative objects were purposefully kept simplistic, with more focus on volumes, light, materials.
  • Analyze those same reference photos for light and material properties. Then materialize with strict rules: no photo textures, only single-color physically based materials or a limited set of procedural (code-generated) materials, IES light profiles, and measured daylight.
  • Create the model in code so the model can be re-generated with different parameters and logic — specifically, different lighting scenarios. Then simply run the code to create the geometry and objects, then render camera views.

Findings:

  • 84 minutes of generation time, about half AI processing and half Blender rendering (MacBook Pro w/ M4 Pro, GPU-accelerated rendering); about €15 in AI token cost
  • Surprisingly good: light matching, procedural materials, mesh topology, overall dimensional precision and stability, world understanding (e.g. object naming)
  • Surprisingly bad: angular estimation, e.g. incorrect vertical angles on pillow placement, complex see-through materials (e.g. dinner lamps)

Process

From input to output

01

Inputs

Seven phone photos, a basic floor plan, a list of known products and a few hard measurements.

  • ceiling 3.10 m
  • cupboard 3650 × 960 mm
  • counter 65 cm deep, 98 cm high
  • TV 755 × 480 mm
  • 14 named products

Goal: a relightable scene for testing a light plan. Light quality first, then surfaces, then object detail.

02

Look up real dimensions

A few 'known' objects can be looked up (by AI) to retrieve precise dimensions, providing scale for the scene.

03

Read reference points off the photos

A pixel grid over each photo; about 60 points and edges are picked where the 3D position is already known, e.g. ceiling corners, door frame, cupboard ends.

Photo 2 with measuring grid, 50 px steps
04

Solve cameras and layout together

A least-squares solve finds the seven camera poses and twelve unknown positions. Mean error about 6 px at 1800 px width.

05

Place everything else by ray-casting

With cameras solved, ray casting is used to solve other anchor points.

Then, points seen from two or more photos are cross-checked.

06

Build the scene from code

Python code. Every object is generated with actual dimensions, bevelled edges, name, etc. The whole scene is re-built in a few seconds.

07

Lighting

Sky and sun set to the photo time (sun 12° above the horizon). Each lamp is a fixture plus a source with a lumen value and a generated IES beam profile.

Measured in the renderer: IES data renders at about 178 lm per watt; daylight is scaled to match.

08

Render, compare, correct

Each render uses the solved camera of its photo, so differences show directly. About 10 s for a preview, 2 min for a 2000 px frame on the GPU.

The first render crashed on a corrupt GPU shader cache. After a cache reset, renders run in a separate background process.

A review pass then applied 18 corrections, all as script changes.

Mesh

Modelled mesh vs reconstructed mesh

Our approach creates clean topology as opposed to scans that tend to generate bad geometry that cannot be cleaned up effectively. See below for a simulated comparison.

Modelled from photos Scan mesh / photogrammetry Gaussian splat
Geometry Separate named objects, edges follow the form One fused triangle surface No mesh; millions of coloured blobs
Unseen sides Modelled from known dimensions Holes or guessed fill Missing or blurred
Lighting Computed; lamps can be changed Captured in the texture Captured with the scene
Editing Move, swap or resize any object Needs cleanup and re-topology Limited
Capture A few photos plus measurements; modelled in code Many overlapping photos or a scanner; automatic Many overlapping photos; automatic
As-found detail Only what is modelled High, including clutter High, including clutter
Materials

Surfaces without image files

Most surfaces are a plain colour with tuned roughness. Three are procedural: computed from position by a small node graph.

Procedural Image texture
Resolution Computed per pixel at any distance Fixed by the image size
